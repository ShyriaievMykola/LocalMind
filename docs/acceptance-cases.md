# Приймальні кейси

Фіксований список наскрізних сценаріїв, за якими перевіряється функціональна коректність продукту (критерій C1).
Оцінка C1 = **пройдені кейси / усього кейсів у цьому списку**.

> **Статус документа:** чернетка (задача S-11, #157), потребує погодження командою в рев'ю.
> Після погодження список **не змінюється** без окремого рішення, записаного в [decisions.md](decisions.md).
> Кейси складені для поточного `main`: усе, чого в ньому ще немає (екрани акаунта й бекапу A-09/A-10, контекст
> результату A-14), у список не входить — див. «Що не входить».

## Правила

- Кожен кейс має передумови, кроки й очікуваний результат, які однозначно перевіряються. Колонка «Посилання» —
  issue, за яким реалізовано функцію, і загроза з [threat-model.md](threat-model.md), яку кейс перевіряє.
- Спосіб перевірки: **CLI** — команди з розділу «Стенд»; **UI** — вручну в десктопному застосунку; **HTTP** — `curl`
  до локального сервера; **Авто** — є автотест (вказано назву), вручну кроки не обов'язкові.
- Колонку «Результат» заповнюємо під час прогону перед кожним чекпоінтом: ✅ пройдено · ❌ не пройдено · — не прогнано.
- Тестові файли: `tests/LocalMind.Core.Tests/TestData/` (формати, пошкоджені файли) і `eval/datasets/demo/corpus/`
  (шість нотаток для пошуку).

## Стенд

Усі шляхи — від кореня репозиторію. Потрібен .NET 10 SDK і модель `multilingual-e5-small`
(`./scripts/download-models.sh` або `.\scripts\download-models.ps1`).

**CLI** (окрема база, щоб не чіпати робочу; `rm` — очистити її перед кейсом, коли це сказано):

```bash
export LocalMind__Storage__DatabasePath=/tmp/ac/ac.db
alias lm='dotnet run --project src/LocalMind.Cli --'
lm index eval/datasets/demo/corpus
lm search "що робити, щоб легше заснути" --mode semantic --k 3
```

Режими `--mode keyword|semantic|hybrid` (за замовчуванням hybrid), `--k` — кількість результатів. Код виходу:
0 — успіх, 1 — помилка або є файли, які не вдалося обробити, 130 — скасовано.
Модель за замовчуванням береться з `models/multilingual-e5-small/`; інший шлях задають змінними
`LocalMind__Embedding__ModelPath` і `LocalMind__Embedding__TokenizerPath`.

**Сервер** (HTTP, локально; ключ JWT генерується на місці й у репозиторій не потрапляє):

```bash
export ASPNETCORE_ENVIRONMENT=Production ASPNETCORE_URLS=http://127.0.0.1:5199
export Jwt__SigningKey="$(openssl rand -base64 48)"
export ConnectionStrings__Server="Data Source=/tmp/ac/server.db" Storage__RootPath=/tmp/ac/backups
export Storage__MaxBackupBytes=1048576 Admin__Email=root@localmind.test Admin__Password="<пароль ≥12 символів>"
dotnet run --project src/LocalMind.Server -c Release --no-launch-profile
B=http://127.0.0.1:5199/api/v1
```

Пароль не повинен містити локальної частини email (`root`). Далі `<token>` — access-токен з відповіді
`POST $B/auth/login`, `<refresh>` — refresh-токен, `<id>` — GUID бекапу. Ліміт `auth`-ендпоінтів — 20 запитів на
хвилину з однієї адреси: між серіями кейсів AC-24…AC-26 чекайте скидання вікна (відповідь `429`).

## Що не входить

- Екрани «Акаунт» і «Бекап» у застосунку (#114, #115) і перегляд контексту результату (#119): їх ще немає в `main`.
  Після злиття команда окремим рішенням додає кейси «реєстрація/вхід у застосунку» й «бекап → відновлення на чистій установці».
- Продуктивність на ~1000 документів і кросплатформенний прогін (Windows / Linux / macOS): потребують окремого
  стенда й датасету (див. EV-07, D-01); за потреби додаються окремим рішенням.
- Угадування паролів шифрування, rollback бекапу сервером (B-03, залишковий ризик R-03) — описано в моделі загроз.
