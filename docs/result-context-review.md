# Перевірка контексту результату (#119)

Перед запуском перебудувати актуальну версію:

```powershell
dotnet build LocalMind.slnx --configuration Release -p:CI=true
if ($LASTEXITCODE -eq 0) {
    .\TestResults\SearchViewPreview\Start-SearchPreview.ps1
}
```

Preview-скрипт і його демо-база локальні та не входять до репозиторію. Для звичайного запуску можна
використати `dotnet run --project src/LocalMind.App --configuration Release` з власними налаштуваннями моделі.
У бібліотеці для перевірки потрібен документ із щонайменше трьома фрагментами й різними словами в кожному;
короткі нотатки демо-бази можуть містити лише один фрагмент. Кількість фрагментів видно в бібліотеці.

Поточне обмеження підсвітки: панель показує повний текст фрагментів, але переносить лише готові
діапазони збігів із короткого уривка картки (типово до 300 символів). Збіги поза цим вікном,
зокрема на початку того самого знайденого фрагмента, не підсвічуються. Попередній і наступний
фрагменти також показуються без підсвітки слів запиту. Якщо в картці немає підсвічених слів,
у розгорнутому контексті їх теж не буде. Кольорове виділення всього знайденого фрагмента
позначає його місце серед сусідів і не означає, що всі збіги запиту в ньому підсвічено.

Повну підсвітку можна реалізувати окремою задачею: передати початковий пошуковий запит у VM
і для кожного з трьох фрагментів побудувати `SnippetBuilder.Build(chunk, query, int.MaxValue)`.

1. Знайти слово із середини документа. До натискання «Більше контексту» картка показує звичайний уривок.
2. Розгорнути контекст. Очікуються підписи «Попередній фрагмент», «Знайдений фрагмент», «Наступний фрагмент»
   і три повні фрагменти в порядку документа; лише знайдений фрагмент
   має кольорове виділення й підпис «Знайдений фрагмент».
   Слова з підсвіткою в короткому уривку картки також виділені напівжирним і підкресленням
   у повному знайденому фрагменті. Перевірити збіг далеко від початку фрагмента:
   підсвітка має залишатися на тих самих словах, повний текст показується без додаткових «…».
   За поточної реалізації інші входження того самого слова поза вікном короткого уривка
   та в сусідніх фрагментах залишаються без підсвітки.
3. Повторити для першого й останнього фрагментів: показуються два фрагменти; для документа з одним
   фрагментом — лише він. Текст не обрізається, довгий контекст прокручується вертикально.
4. Згорнути й відкрити панель знову. Перевірити кілька карток, вузьке вікно та світлу/темну тему.
   У темній темі текст виділеного фрагмента білий.
5. Натиснути «Відкрити файл»: відкривається джерело саме цієї картки. Якщо файл видалений,
   помилка показується в картці, застосунок продовжує працювати.
6. Змінити документ і дочекатися переіндексації, потім відкрити контекст старого результату:
   очікується повідомлення «Документ змінено або видалено. Виконайте пошук знову.».
7. Перевірити Ctrl+K, ↑/↓, Enter для відкриття вибраного файла та Esc для очищення результатів.
   Новий пошук і очищення не повинні повертати старі панелі або їхні помилки.

Автотести `ResultContextTests` додатково перевіряють помилку читання і повтор, скасування запитів,
застарілі відповіді та повторне відкриття в обох порядках завершення запитів.
`DocumentRepositoryTests` перевіряють запит на справжньому SQLite, включні межі, порядок, ізоляцію
документів, порожні результати, некоректний діапазон і скасування.
