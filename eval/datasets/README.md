# Датасети для оцінки пошуку

Датасет — тека, яку приймає `localmind eval --dataset <тека>`. Приклад: [`demo/`](demo).

```
<датасет>/
├── corpus/          документи (будь-які формати, які вміє індексувати LocalMind), можна з підтеками
├── queries.jsonl    запити
└── qrels.jsonl      розмітка: які документи відповідають на які запити
```

## queries.jsonl

Один JSON-об'єкт на рядок:

```json
{"id": "q01", "text": "режим WAL SQLite", "type": "exact"}
```

| Поле | Значення |
|---|---|
| `id` | унікальний в межах датасету |
| `text` | текст запиту, не порожній |
| `type` | `exact` — точні слова й терміни; `paraphrase` — те саме іншими словами; `crossLingual` — запит однією мовою, документ іншою |

Метрики рахуються окремо за кожним типом: `exact` має показати силу BM25, `paraphrase` і `crossLingual` — semantic.

## qrels.jsonl

```json
{"query": "q06", "document": "embeddings.md", "relevance": 3}
```

- `document` — шлях відносно `corpus/` з `/` як роздільником.
- `relevance`: **1** — відповідає частково, **2** — добре, **3** — ідеальна відповідь. Нерозмічений документ вважається нерелевантним.
- Розмітка на рівні **документів**, а не фрагментів: ідентифікатори фрагментів змінюються при кожній індексації, а межі залежать
  від розміру фрагмента (експеримент E3), тож розмітка за фрагментами зробила б датасет непридатним для порівняння.
- Кожен запит має хоча б один релевантний документ.

## Перевірка

Завантажувач (`EvalDatasetLoader`) зупиняється з повідомленням «файл, рядок, причина» при: порожньому запиті, дубльованому `id`,
невідомому `type`, посиланні на неіснуючий запит чи документ, `relevance` поза 1…3, повторній розмітці пари, запиті без розмітки.

## Метрики

- **Recall@k** — частка релевантних документів у перших k.
- **MRR** — обернений ранг першого релевантного документа.
- **nDCG@10** — з лінійним виграшем (`relevance` як виграш), нормований на ідеальний порядок.

Результат пошуку (фрагменти) згортається до документів: береться перша поява документа в списку.

## Запуск

З кореня репозиторію (модель береться відносно поточної папки; для semantic і hybrid вона має бути завантажена):

```bash
dotnet run --project src/LocalMind.Cli -c Release -- eval --dataset eval/datasets/demo
```

Корпус індексується в тимчасову базу, бібліотека користувача не чіпається. Результат — CSV і Markdown у `eval/results/`
(`--output` змінює теку), таблиця для всіх режимів: метрики загалом і за типами запитів, p50/p95 часу пошуку; зверху —
час індексації, розмір бази, пікова пам'ять. На macOS ОС не віддає справжній пік пам'яті процесу, тож там
рахується найбільший із замірів після індексації та кожного режиму (оцінка знизу); на Windows і Linux — справжній пік.

| Параметр | Значення |
|---|---|
| `--dataset <тека>` | обов'язковий |
| `--mode keyword semantic hybrid` | які режими проганяти (за замовчуванням усі три) |
| `--k 10` | глибина метрик |
| `--config experiment.json` | кілька прогонів в одному запуску, замінює `--mode` і `--k` |

Конфіг експерименту: `{"runs": [{"name": "bm25", "modes": ["keyword"], "k": 10}, {"name": "all", "modes": ["keyword", "semantic", "hybrid"]}]}`.
Корпус індексується один раз на весь файл; налаштування нарізки й моделі змінюються через `appsettings.json` або змінні
оточення `LocalMind__Chunking__...` / `LocalMind__Embedding__...` між запусками.

## Приватність

У Git — лише відкриті або власноруч написані тексти. **Особисті нотатки, листування, документи з іменами, адресами,
паролями чи токенами в репозиторій не потрапляють**, навіть «для тесту». Реальний особистий корпус тримайте поза репозиторієм
і передавайте шлях через `--dataset`.
