# Розмітка запитів на відкритому корпусі (R-02)

Інструменти й протокол розмітки `queries.jsonl` і `qrels.jsonl` для датасету `datasets/open` (корпус з R-01: `corpus/`, `manifest.jsonl`).
Формат датасету — [eval/datasets/README.md](../../README.md). Самі дані (корпус, запити, оцінки) у Git не потрапляють.

Розмітку роблять агенти, команда перевіряє вибірку (`sample-for-humans.md`). Протокол обов'язковий: він захищає результати E1–E3 від упередженості.

## Протокол

1. **Запити пишуться від документа, а не від видачі.** `label.py sample` бере стратифіковану вибірку документів із маніфесту (мови, джерела,
   теми), `label.py show <id>` показує документ. Пошук LocalMind при написанні запитів **не відкривається і не запускається**: інакше запит
   підлаштується під те, що система й так знаходить. Для 90 запитів по 30 кожного типу:
   - **exact** — рідкісні терміни, назви, числа з документа; усі значущі слова запиту є в тексті;
   - **paraphrase** — той самий зміст **без жодного значущого слова документа**: ні форми слова, ні тієї самої основи; стоп-слова допускаються. Перевіряє `check-queries`;
   - **crossLingual** — запит однією мовою, документ іншою. Версії тієї самої статті іншими мовами (групи з маніфесту) автоматично потрапляють у qrels з оцінкою 3.

   Мови запитів: uk і en переважно, кілька de/pl/fr; **російської немає** (перевірка за літерами ы, э, ъ, ё в запитах мовою uk і за полем мови).
2. **Пулінг.** Для кожного запиту береться top-10 із `keyword`, `semantic` і `hybrid` (CLI `localmind search`), результати об'єднуються за документом;
   до пулу додається документ-джерело. Якщо обсяг оцінок завеликий, пул скорочується до top-7 (`--top 7`).
3. **Оцінка кожного кандидата 0–3** за текстом фрагмента й заголовком, за інструкцією нижче. Нулі в `qrels.jsonl` не пишуться, але лишаються в `judgments.jsonl`.
4. **Файли.**

   | Файл | Що |
   |---|---|
   | `queries.jsonl`, `qrels.jsonl` | у теці датасету; формат eval/datasets/README.md |
   | `labeling/sample.jsonl` | документ-джерело й тип кожного запиту (мета) |
   | `labeling/pool.jsonl` | сирий пул: запит, режим, ранг, шлях, уривок |
   | `labeling/candidates.jsonl` | кандидати на оцінку (з фрагментом і заголовком); `auto: true` — джерело й переклади |
   | `labeling/judgments.jsonl` | **усі** оцінки, включно з нулями, з полями `by` і `how` |
   | `labeling/sample-for-humans.md` | 30 пар для перевірки командою |

## Інструкція з оцінювання (версія 1)

Оцінюється, наскільки **фрагмент** (і заголовок документа) відповідає **потребі, що стоїть за запитом**, а не тому, чи збігаються слова. Дивіться лише на
текст кандидата й запит; не оцінюйте за тим, у якому режимі кандидат знайдено й який він за рангом.

| Оцінка | Значення | Приклад |
|---|---|---|
| **3** | Ідеальна відповідь: фрагмент прямо відповідає на запит або це саме той документ, про який питали; більше нічого шукати не треба | запит «як вимкнути режим WAL» → фрагмент, де описано `PRAGMA journal_mode`; версія тієї самої статті іншою мовою |
| **2** | Добра відповідь: відповідає на запит по суті, але неповно, у загальнішій чи сусідній формі, або потрібна відповідь у наступному абзаці того ж документа | стаття про SQLite в цілому, де є розділ про WAL |
| **1** | Часткова відповідь: стосується теми запиту, містить корисну дотичну інформацію, але відповіді на запит не дає | документ про бази даних без згадки про режим журналу |
| **0** | Не відповідає: збіг лише слів чи випадковий, інша тема, інший сенс слова | «Java» (острів) для запиту про мову програмування |

Правила:

- Оцінюйте мовою запиту «в сенсі», а не буквально: переклад чи переказ тієї ж інформації іншою мовою оцінюється так само, як оригінал.
- Однакова оцінка для однакового вмісту: якщо в пулі кілька версій тієї самої статті, ставте їм однакові оцінки.
- Сумнів між двома оцінками → нижча. Якщо фрагмента замало для рішення, відкрийте документ (`context` у `candidates.jsonl` — це вікно навколо знайденого місця).
- Документ-джерело й переклади тієї ж статті (`auto: true`) отримують 3 автоматично, їх не оцінюють.
- Поле `by` — хто оцінював (ім'я агента), `how` — за чим (наприклад, `фрагмент+заголовок, інструкція v1`), необов'язкове `note` — коротке пояснення нестандартного рішення.
- Запис оцінки: `{"query": "q001", "document": "wikipedia/en/x.md", "grade": 2, "by": "агент", "how": "фрагмент+заголовок, інструкція v1", "note": ""}`;
  для документа береться найвища оцінка серед його фрагментів, якщо їх кілька.

## Команди

З кореня репозиторію, `<корпус>` — тека `corpus/`, `<маніфест>` — `manifest.jsonl`, `<датасет>` — тека `datasets/open`.

```bash
L=eval/datasets/open/labeling/label.py

# 1. Вибірка документів-джерел і читання документа (запити пишуться тут, без пошуку)
python $L sample --manifest <маніфест> --out <датасет>/labeling/sample.jsonl
python $L show --sample <датасет>/labeling/sample.jsonl --corpus-root <корпус> q001

# 2. Перевірка запитів за протоколом (paraphrase без спільних слів, мови, без російської, мова crossLingual)
python $L check-queries --queries <датасет>/queries.jsonl --meta <датасет>/labeling/sample.jsonl --corpus-root <корпус>

# 3. Індексація корпусу в окрему базу й пулінг (CLI: dotnet run ... ; потрібна модель multilingual-e5-small)
python $L index --corpus-root <корпус> --db <датасет>/labeling/eval.db
python $L pool --corpus-root <корпус> --db <датасет>/labeling/eval.db --queries <датасет>/queries.jsonl --out <датасет>/labeling/pool.jsonl --top 10

# 4. Кандидати на оцінку (з фрагментами), оцінки пишуться у judgments.jsonl, перевірка повноти
python $L candidates --queries <датасет>/queries.jsonl --meta <датасет>/labeling/sample.jsonl --pool <датасет>/labeling/pool.jsonl --manifest <маніфест> --corpus-root <корпус> --out <датасет>/labeling/candidates.jsonl
python $L check-judgments --candidates <датасет>/labeling/candidates.jsonl --judgments <датасет>/labeling/judgments.jsonl

# 5. qrels і вибірка для людей, перевірка завантажувачем датасету
python $L build --queries <датасет>/queries.jsonl --candidates <датасет>/labeling/candidates.jsonl --judgments <датасет>/labeling/judgments.jsonl --out-dir <датасет>
python $L human-sample --queries <датасет>/queries.jsonl --candidates <датасет>/labeling/candidates.jsonl --judgments <датасет>/labeling/judgments.jsonl --out <датасет>/labeling/sample-for-humans.md
dotnet run --project src/LocalMind.Cli -c Release -- eval --dataset <датасет> --mode keyword
```

`index` і `pool` викликають `dotnet run --project src/LocalMind.Cli -c Release --`; інший виклик (наприклад, опублікований `localmind`) задається `--cli "localmind"`.
Для `eval` датасет — тека з `corpus/`, `queries.jsonl`, `qrels.jsonl` (корпус можна підкласти посиланням). Запитів `eval` без моделі не обробляє у режимах semantic і hybrid.

Тести інструментів: `python -m unittest discover -s eval/datasets/open/labeling -p "test_label.py"`. Потрібен лише Python 3.10+.

## Перевірка командою

`sample-for-humans.md` — 30 пар «запит → документ (фрагмент) → оцінка агента» з порожньою колонкою «згоден/ні». Вибірка рівномірна за оцінками 0/1/2/3
(щоб серед пар були й релевантні, а не самі нулі). За частку «згоден» можна оцінити узгодженість агентної розмітки з людською; помітні розбіжності —
привід переглянути інструкцію й повторити оцінку для відповідного типу запитів.
